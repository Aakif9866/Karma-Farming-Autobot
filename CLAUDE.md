# CLAUDE.md — Karma Farming Autobot

Personal Reddit trend-intelligence + content-assistance platform (Indian + global communities). It finds trends, memes and opinions, explains them with traceable metrics, and drafts original content that **the user approves and posts themselves**. The docs in `docs/` are the source of truth; read the relevant one before touching a module.

## Hard rules (never violate)

1. **No platform abuse.** No vote actions, no automated, scheduled or bulk posting, no scraping, no ban evasion. Authorized Reddit Data API only, ≤ 60 QPM. Publishing (later phase) = one explicit user click per approved draft.
2. **$0 paid APIs.** LLM = **Groq free tier only** (ADR-013). No paid providers, no credit card on Groq. Embeddings (fastembed) and OCR (Tesseract) run locally.
3. **No NSFW.** Drop `over_18` posts at ingestion and reject NSFW subreddits (ADR-014).
4. **No fake integrations.** Never pretend an external API works. Mock data is only for development, always `source="mock"`, and shown with a MOCK banner in the UI.
5. **No secrets in the repo.** Env vars only; `.env` is gitignored; `.env.example` has placeholders.
6. **No media storage.** Fetch previews transiently, keep only derived features + Reddit URLs (ADR-006).
7. **Never invent personal experiences** in drafts. Use `[YOUR EXPERIENCE: …]` placeholders; drafts with unfilled placeholders can't be approved.
8. **Reddit text is untrusted input.** Pass it to LLMs as delimited data with schema-only outputs and no tools (prompt-injection posture).
9. **Never skip failing tests silently.** Do not start a dependent phase before the current phase's acceptance criteria pass (see `docs/PHASES.md`).
10. **Don't modify global Claude Code settings** (`~/.claude/*`) without explicit permission.

## Architecture (summary, details in docs/SYSTEM_ARCHITECTURE.md)

- **Modular monolith.** `backend/` (FastAPI + SQLAlchemy 2 + Pydantic v2 + Alembic) runs as 3 processes from one image: `api`, `worker` (Celery), `beat` (Celery Beat). `frontend/` is Next.js (App Router) + TS strict + Tailwind + shadcn/ui + Recharts + TanStack Query.
- **Data**: PostgreSQL 16 + pgvector (384-d embeddings), Redis (broker + cache + Groq per-minute token window).
- **AI**: small per-job LangGraph graphs (`daily_report`, `generate_drafts`, `analyze_*`); `collect_cycle` is a plain Celery chain with no LLM. One LLM entry point: `agents/llm.py::structured(task, schema, messages)`. Task → model mapping lives in config: cheap `openai/gpt-oss-20b`, strong `openai/gpt-oss-120b`, vision `qwen/qwen3.8-27b`.
- **Groq free-tier limits are per model**: 30 RPM, 1K req/day, **8K tokens/min**, 200K tokens/day. Keep every call ≤ ~7K tokens; the per-model daily cap is 160K; a run that hits the cap becomes `deferred_budget`.
- **Dependency direction**: `api → services → (repositories | intelligence | ingestion | meme_analysis | agents | analytics) → models`. Routers never touch the ORM. Repositories hold no business logic.

```
backend/app/{api/v1,core,models,schemas,repositories,services,ingestion,intelligence,meme_analysis,agents,analytics,workers}
backend/{alembic,config/taxonomy.yaml,config/scoring.yaml,tests}
frontend/{app,components,lib}
docs/  scripts/  infrastructure/
```

## Coding conventions

**Python** (3.12+, managed with `uv`)
- Type everything; `mypy --strict` clean. `ruff check` + `ruff format`.
- Pydantic v2 models for all I/O; SQLAlchemy 2.0 typed `Mapped[]` style.
- Pure functions in `intelligence/` and `meme_analysis/` (data in, result out), so they can be tested without a DB.
- Deterministic Python for filtering, metrics and scoring. Call the LLM only where language understanding is required.
- `structlog` JSON logging with `run_id` / `job_id` / `subreddit`. No `print`.
- Raise domain exceptions (`core/errors.py`) and map them to the error envelope in one place.
- Config through `core/settings.py` (pydantic-settings) only. Never `os.environ` elsewhere.
- Files stay under ~300 lines; split by responsibility, not by layer count.
- No abstraction without two real implementations (no single-impl interfaces or factories).

**TypeScript** (`pnpm`)
- `strict: true`; no `any`. API types come from `openapi-typescript`, never hand-written duplicates.
- Server components for initial data, TanStack Query for interactive filters and pagination.
- Every data view has loading (skeleton), empty, error and paginated states. **No non-functional buttons.**
- Dark-first theme tokens (near-black/charcoal surfaces, single green accent). Use shadcn/ui primitives before writing custom ones.

**Database**
- UUID PKs; Reddit fullnames stored as unique columns. `timestamptz` in UTC.
- Every schema change is an Alembic revision, autogenerated and then hand-reviewed. Destructive changes go expand → migrate → contract.
- Every score row stores its `score_breakdown` jsonb + config version (explainability).

## Development workflow

1. Read the relevant doc(s) + `docs/IMPLEMENTATION_STATUS.md` before starting.
2. Work one phase at a time (`docs/PHASES.md`). Within a phase, take small vertical slices.
3. After each meaningful change: run tests + lint + types → update docs → **commit and push** (the user wants GitHub kept in sync). Conventional commit prefixes: `feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`.
4. Repo-local git identity is set (Aakif9866, personal SSH key via `core.sshCommand`). Don't change it.
5. At the end of a phase, run the `/phase-reviewer` skill, then stop and wait for user approval before the next phase.

## Documentation requirements

- Diagrams are Mermaid.

## Testing requirements (details in docs/TESTING_STRATEGY.md)

- PR tests make **no network calls**: Reddit is mocked with `respx` + synthetic fixtures, the LLM with `FakeLLM`.
- Integration tests use real Postgres+pgvector and Redis (compose/CI services).
- Every bug fix gets a regression test. `xfail` needs a reason + issue link.
- Coverage target: 80% for `intelligence/`, `ingestion/`, `services/`.
- LLM evals (`pytest -m eval`) hit the real Groq API and are run manually or nightly, never in PR CI.
